Weaver uses exactly one ambient operator identity: the Claude Code login already active on the machine. It does not mint, extract, copy, store, pool, or rotate Claude authentication tokens, and it never cycles through accounts to get around a provider limit.

## How Agent SDK plan usage works

Since June 15, 2026, Agent SDK and `claude -p` usage no longer consumes the interactive usage allowance included with a paid Claude plan. Anthropic instead gives eligible Max 20 users a separate $200 monthly Agent SDK credit after a one-time claim. Anthropic defines that credit as per-user, not pooled or transferable. See Anthropic's current [Agent SDK with a Claude plan guide](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan) for eligibility and the claim flow.

When the included Agent SDK credit is gone, the supported overflow is Anthropic **usage credits**. Open Claude Code and run `/usage-credits` to enable them and set the provider-side spend cap you are comfortable with. Anthropic documents the controls in [Manage usage credits for paid Claude plans](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans).

<Warning>
  Enabling usage credits authorizes additional spend with Anthropic. Weaver never enables them for you. Weaver's dashboard dollar figure is an SDK-reported runaway estimate, not an Anthropic billing limit; set the real cap in Claude's usage-credit controls.
</Warning>

## What happens when capacity runs out

A credit, rate-limit, overload, or authentication failure is infrastructure state, not evidence that the workstream failed:

1. Weaver closes the disposable model attempt without accepting any claimed work.
2. The assignment and organizational position remain in durable typed state. No SDK session or model context stays alive.
3. Weaver records a delayed infrastructure-backoff wake and updates `WorkstreamDoc.capacity`, the typed source of truth. Capacity entries are kept per model because coordinator and worker models can recover independently.
4. The runner periodically probes each affected Claude model. A Claude credential-file metadata change also prompts a probe; Weaver never reads or copies the credential value.
5. When a model's probe passes, Weaver pulls matching backed-off workstreams forward and fresh processes continue from their stored projections.
6. Because capacity pools are per model, a limited **primary coordinator model degrades instead of parking**: while the primary's pool (e.g. a Fable weekly limit) is in backoff and the fallback's isn't, coordinator passes run on the fallback (`claude-opus-5` by default, `WEAVER_COORDINATOR_FALLBACK_MODEL` to override), each pass records which model it actually ran on, and the probe restores the primary the moment its pool recovers. Both pools limited means genuine parking — the fallback never cascades further down.

This makes an outage cost waiting rather than duplicated model work or a retry storm. Killing and restarting Weaver during the wait changes nothing.

Sustained capacity trouble becomes one deduplicated operator card instead of permanent silent waiting: Agent SDK credit and authentication failures surface after three consecutive backoffs; session and rate limits get twelve attempts to self-clear first. Recovery resolves the card automatically. The card can explain how to recover, but it cannot enable spend or change identity.

## Recover explicitly

- **Included credit not claimed:** follow Anthropic's one-time claim flow in the [Agent SDK plan guide](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).
- **Included credit exhausted:** open Claude Code, run `/usage-credits`, and choose a spend cap. Weaver resumes after its next successful probe.
- **Login expired or changed:** run `claude auth login` and reauthenticate manually. Weaver resumes after a successful periodic probe; when file-backed credential metadata changes, it probes immediately. It never handles the credential itself.

There is deliberately no “add another Claude account” setting. [Anthropic's Consumer Terms](https://www.anthropic.com/legal/consumer-terms) prohibit sharing account credentials and bypassing protective measures, and Agent SDK credits are per-user and non-poolable. For shared or production automation, use Anthropic's supported Platform API-key path described in the [Agent SDK plan guide](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), with an organizational billing and credential model designed for that deployment. Weaver's subscription mode remains single-operator.
